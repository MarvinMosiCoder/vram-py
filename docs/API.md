# API Reference

Base URL: `http://localhost:8000`

Interactive, always-up-to-date docs (generated by FastAPI from the code)
are available at `http://localhost:8000/docs` while the backend is
running — this file is a human-readable companion to that.

## Authentication

All routes except `POST /register` and `POST /login` require a JWT,
obtained from `POST /login`, sent as:

```
Authorization: Bearer <token>
```

Tokens expire 60 minutes after issue (`ACCESS_TOKEN_EXPIRE_MINUTES` in
`backend/app/core/auth.py`). There is no refresh endpoint — an expired token
means logging in again.

A request with a missing, invalid, or expired token gets:

```json
// 401 Unauthorized
{ "detail": "Could not validate credentials" }
```

A request from a correctly authenticated user whose role isn't allowed
for that route gets:

```json
// 403 Forbidden
{ "detail": "Requires one of these roles: admin" }
```

## `POST /register`

Create a new user. Open to anyone (no auth required) — this is a demo
template, not a production-safe default.

**Request body** (`application/json`)

| Field | Type | Required | Notes |
|---|---|---|---|
| `email` | string (email) | yes | must be unique |
| `password` | string | yes | stored as a bcrypt hash, never in plain text |
| `role` | string | no | one of `admin`, `editor`, `viewer` — defaults to `"viewer"`; must already exist (created by `seed.py`) |

```json
{
  "email": "new.user@vram.com",
  "password": "hunter2",
  "role": "editor"
}
```

**Response** `200 OK`

```json
{ "id": 4, "email": "new.user@vram.com", "role": "editor" }
```

**Errors**

| Status | Cause |
|---|---|
| `400` | email already registered |
| `400` | `role` doesn't match an existing role |
| `422` | validation error (e.g. malformed email, missing field) |

## `POST /login`

Exchange email + password for a JWT. Body is **form-encoded**, not
JSON — this endpoint uses FastAPI's `OAuth2PasswordRequestForm`, which
expects fields literally named `username` and `password` (send the
user's email as `username`).

**Request body** (`application/x-www-form-urlencoded`)

```
username=admin@vram.com&password=admin123
```

**Response** `200 OK`

```json
{ "access_token": "eyJhbGciOi...", "token_type": "bearer" }
```

**Errors**

| Status | Cause |
|---|---|
| `401` | no user with that email, or password doesn't match |

## `GET /me`

Returns the profile of the currently authenticated user, resolved from
the JWT. Used by the frontend on page load to turn a saved token back
into a user object.

**Auth:** any authenticated user

**Response** `200 OK`

```json
{ "id": 1, "email": "admin@vram.com", "role": "admin" }
```

---

## `GET /dashboard`

Example route open to any logged-in user regardless of role.

**Auth:** any authenticated user

**Response** `200 OK`

```json
{ "message": "Welcome admin@vram.com, your role is admin" }
```

---

## `GET /editor/content`

Example route restricted to content-producing roles.

**Auth:** role `admin` or `editor`

**Response** `200 OK`

```json
{ "message": "Editor content area" }
```

**Errors:** `403` if role is `viewer`.

---

## `GET /admin/users`

Lists every registered user. The route the frontend's "Total users"
dashboard card calls.

**Auth:** role `admin` only

**Response** `200 OK`

```json
[
  { "id": 1, "email": "admin@vram.com", "role": "admin" },
  { "id": 2, "email": "some.editor@vram.com", "role": "editor" }
]
```

**Errors:** `403` if role is `editor` or `viewer`.

## Route summary

| Method | Path | Auth |
|---|---|---|
| POST | `/register` | none |
| POST | `/login` | none |
| GET | `/me` | any logged-in user |
| GET | `/dashboard` | any logged-in user |
| GET | `/editor/content` | `admin`, `editor` |
| GET | `/admin/users` | `admin` |

See [ARCHITECTURE.md](ARCHITECTURE.md) for how the auth/RBAC dependency
chain behind these routes is wired together.
